# Port type / connector audit — findings

Generated by `scripts/audit-port-types.js` (`npm run audit:ports`), which materialises
every catalogue spec through `new Topology().addDevice(spec)` and compares the cage the
engine resolves for each port against the type that port declares.

- Catalogue: **878 models / 188 vendors / 11,340 physical ports**
- Offending: **2 devices, 64 ports** — all severity `high`
- Raw data: `research/incoming/audit-port-types.json`
- Exit code is `1` while any offender exists, so CI can gate on it.

## What was checked

| Rule | Requirement |
|---|---|
| `wireless-not-antenna` | `type: wireless` must resolve to the `antenna` cage |
| `console-not-console`, `coax-not-coax`, `dsl-not-dsl`, `powerline-not-powerline` | line type must resolve to its own connector family |
| `pon-not-optical-connector` | `type: pon` must resolve to `sc-apc`, `sc-upc`, `lc-upc` or `lc-apc` |
| `ethernet-not-data` | `type: ethernet` must not resolve to `antenna` or `console` |
| `fibre-connector-copper-cage` / `copper-connector-fibre-cage` | declared connector family must match the resolved cage family |
| `unknown-cage` | the resolved cage must actually exist in `media.CAGES` |

The comparison uses the **effective** cage (`media.CAGES[cage] || 'rj45'`), because an
unmodelled cage string does not fail loudly — it silently inherits RJ45 copper media.

## Priority 1 — 64 ports on 2 passive optical devices declare `connector: "lc"`

`lc` is a *medium* connector token in `engine/media.js`, not a cage key. `CAGES` has
`lc-upc` and `lc-apc` but no `lc`, so `derivePortHardware` falls through to
`CAGES.rj45` / `CAGE_MEDIA.rj45`: the port reports `cageName: "RJ45"`,
`family: "copper"`, and offers `10/100/1000BASE-T … 10GBASE-T`. Because `CAGE_MATE`
has no `lc` entry either, `cagesMate('lc', …)` is false for *every* partner, including
another `lc` port, so the link is refused with the nonsensical
`Cannot mate RJ45 to RJ45 (incompatible connectors)`.

| Device | Ports | Detail |
|---|---|---|
| `fs/FMU-D402160M3` | 40 (`ch21`–`ch60`) | 40-channel DWDM mux/demux, LC/UPC channel ports |
| `fs/FHD-1U-PP-24LC` | 24 (`port1`–`port24`) | 24-port LC/UPC fibre patch panel / ODF |

Both are 100% fibre boxes whose every fibre port is presently unusable and drawn as
copper. The fix is in the spec, not the engine: `connector: "lc-upc"` (both devices
document LC/UPC), i.e. the same shape the engine already models for the SDX 611.

## Validation: the audit reproduces the radio bug it was written for

Run against the parent of the fix commit (`9895612`, with `devices/` exported from git
and the current `engine/`), the same script reports 74 offenders on 8 devices:

- `ubiquiti/AF60-XG radio1` — `wireless`, connector `sfp+` → cage `sfp+`
- `siklu/EtherHaul 8010FX radio0` — `wireless`, connector `sfp+` → cage `sfp+`
- `radwin/RADWIN 5000 JET radio0` — `wireless`, connector `sfp` → cage `sfp`
- 7 × `type: pon` ports resolving to `rj45` on `fs/FBT Splitter 1x2 SC/APC`,
  `fs/FHD-PLC1x81SCA`, `fs/FS-FWDM-1310-1490`
- the same 64 `lc` ports

Each rule was also exercised directly against synthetic `(type, connector, cage)`
triples: all seven fire where they should and stay silent on the legal combinations
(`wireless/antenna`, `pon/sc-apc`, `ethernet/rj45`, `ethernet/sfp+`↔`sfp+`).

## Why this needs its own gate

`npm test` is green on exactly this tree (33 suites, 0 failures) while these 64 ports are
dead. `test/hardware-invariants.test.js` asserts type → cage only for
`wireless / console / coax / dsl / powerline / pon`; it does not cover `ethernet`
resolving to `antenna`/`console`, the connector-vs-cage axis, or a cage string that is
not in `media.CAGES`. This audit covers those three and reports rather than asserts, so
a contributor can paste the offending port straight into a fix.

## Known limits

- The audit judges **declarations against the engine**, not declarations against
  datasheets. A port that declares no connector and defaults to RJ45 is invisible here:
  `fs/FMU-D402160M3` `line` and `p1310` are typed `ethernet` with no connector, so they
  are modelled as copper even though the box presents LC/UPC. `scripts/audit-devices.js`
  (prose vs ports) is the companion check for that class.
- Three specs declare a duplicate interface name, so the `Device` interface `Map`
  silently drops one port each: `extreme/VSP 4450GSX-PWR+` (`1:49`, `1:50`) and
  `fiberhome/AN5516-01` (`ge1/1-sfp`). Not a connector defect; reported separately.
- Three `type: ethernet` ports sit in SC cages (`allied-telesis/AT-MC102XL scupc1`,
  `tp-link/FC311A-20 scupc1`, `huawei/HG8010H pon`). The hardware is consistent, the
  *type* label is arguably wrong (a PON port declared as ethernet); outside this rule
  set, worth a follow-up.
