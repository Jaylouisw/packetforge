## What is missing or weak, ranked

1. **Three of the four labs assert nothing about behaviour.** `test/examples-generated.test.js:96-108`
   holds a two-entry `expect` map (`lab1`, `lab2`) and skips every other file; `:42` asserts
   `files.length >= 4` and nothing more. So `lab3` and `lab4` are covered only by "the JSON
   round-trips", which is what a hand-written empty board also passes.
2. **The generator's own self-check cannot fail.** `examples/build-examples.js:147-157` picks a
   source host and destination by filename prefix (`lab1`, `lab2`, `lab4`) and by a generic
   fallback — `PC1` to `10.0.0.30` — for everything else, which is why `lab3` passes there by
   coincidence. It prints the outcome and exits 0 either way: `process.exitCode` and `process.exit`
   appear nowhere in the file, and CI runs it (`docs/CI.md:51`). A new lab whose `PC1` cannot reach
   `10.0.0.30` prints `PING FAILED` into a green step.
3. **Ten protocol families ship with no artefact a person can open.** The only way to see OSPF work
   today is to read `test/show-ospf.test.js`. A lab is the one artefact that exercises the whole
   stack at once — config words, engine, console, serializer — and it is importable.
4. **Delay is invisible.** 16 of 16 links are `lengthM: null`, so the feature that separates this
   simulator from a hop counter produces the same number in every lab.
5. **`flows` and `dhcp` are empty in every document**, so an imported lab opens with an empty
   Simulate tab and `show flows` answering nothing (`engine/topology.js:784,788` write both keys
   back on save — nothing ever writes them first).
6. **Nothing points at a lab.** `grep -rn "examples/lab" docs/*.md README.md` returns no hits;
   `README.md:140` is one line of directory tree. A newcomer who wants to see BGP has no route from
   the docs to a file.

## Steps

Each step is one pull request by one worker, in this order.

1. **Give the generator a declared probe and an exit code.** `S`. `examples/build-examples.js`:
   replace the prefix chain at `:147-157` with a `probe: {from: 'PC1', to: '192.168.1.20'}` field on
   each entry of the `labs` table (`:134-139`), run it, and set `process.exitCode = 1` on a failure.
   `lab3`'s current probe (the `PC1` → `10.0.0.30` fallback) is written down where it can be read
   instead of inherited.
2. **Make the suite read the same table.** `S`. `test/examples-generated.test.js`: delete the
   two-entry `expect` map (`:96-98`) and the `files.length >= 4` assertion (`:42`), and assert, per
   lab, one ping and one protocol fact read back through `runCommands`. `lab4`'s fact is already
   there to be read: SW2's `show spanning-tree` prints `Fa0/8 Altn BLK` and names SW1 as root
   bridge, so the file named `-stp` would start asserting spanning tree. A lab with no declared
   probe fails. Lands before the new labs so the pattern exists when they arrive.
3. **`lab6-ospf-multi-area.json`.** `M`. Four routers, area 0 and area 1, one ABR, one passive
   interface, one `ip ospf cost`. Probe: a ping across the ABR plus `show ip ospf neighbor`
   containing `FULL`. Probed working today on `generic-router` with `ospf router-id 1.1.1.1` /
   `ospf area 0` — the console's dialect, not IOS's `router ospf <pid>` (`engine/cli.js:3067`).
4. **`lab7-ebgp-two-ases.json`.** `M`. Two ASes, one eBGP session each way, an ACL that denies the
   session and then permits it. Probe: `show ip bgp summary` on `1 of 1 neighbour(s) established`
   and the ACL's counter moving.
5. **`lab8-vrrp-gateway.json`.** `M`. Two routers, a virtual address, `priority 120`, two hosts;
   the probe pulls the master's cable and asserts `show vrrp` names the other master.
6. **`lab9-lag-trunk.json`.** `S`. Two switches, a two-member port-channel carrying VLANs 10 and 20.
   Probe: `show etherchannel summary` reporting two bundled and a ping across the bundle (`M` if the
   probe also pulls one member).
7. **`lab10-long-haul-fibre.json`.** `S`. A 40 km pair against a patch lead, one 1G and one 10G
   leg. Probe: `ping` from each side, asserting the long span's round trip exceeds the short one by
   the serialisation-plus-propagation difference — the first lab in the repository where `lengthM`
   is not null.
8. **A coverage gate: every protocol module has a lab, or the suite says so.** `M`,
   **needs Jay's approval** — it makes a new engine module fail CI until a lab names it, which
   changes what a protocol pull request has to contain.
9. **`examples/README.md` and one table in `README.md`.** `S`. Lab → what it shows → the three
   console commands worth typing after import, and a link from each protocol section of
   `docs/CLI.md`. This is the step that pays for itself on the first visit; the labs are already
   importable and already load.

## Risks

- **A lab may only name models the catalogue has.** CI runs
  `scripts/missing-devices.js examples --no-issues` over the built labs (`docs/CI.md:51`), so a lab
  built on a spec that is later renamed breaks a pull request that touched no lab. Build every new
  lab from `generic/*` where the console's dialect allows it (it does — see step 3) and from
  named vendor models only where the point *is* the vendor.
- **The committed JSON must be what the generator produces.** `test/examples-generated.test.js:52`
  compares `serialize()` to the file byte for byte, so a lab is generated, never hand-edited.
- **`serialize()` is a white-list** (`docs/UPSTREAM-DESIGN.md:481`, §5.4): a config key the engine keeps
  in memory and does not write silently vanishes on reload. A lab's probe must therefore assert on
  the *reloaded* device, not the one still in the builder.
- **A lab that exposes an engine defect turns a docs pull request into an engine pull request.** Out
  of scope here: file the defect with the probe's output and keep the lab on the path that works, or
  drop that assertion and leave a `research/` note.
- **Cost is small but not zero:** each lab adds a `missing-devices.js` pass and two round trips. Five
  labs are milliseconds; the real cost is that step 2 makes an untested lab fail, which is the point.

## Test strategy

One probe declaration, three consumers: the generator's self-check, `test/examples-generated.test.js`,
and (step 8) the coverage table. Each probe asserts a *protocol* fact through the console —
`show ip ospf neighbor` says `FULL`, `show ip bgp summary` says established, `show etherchannel
summary` counts two bundled, `show vrrp` names a master — because "it pings" is already true of a
static route and would let a lab named `-bgp` pass with no BGP in it. Plus: two generator runs are
byte-identical, and `npm test` picks the new suite up automatically (`scripts/run-tests.js`
discovers `test/*.test.js`).

## Left out deliberately

`lab5-dual-homed-edge.json` is already spoken for: `docs/UPSTREAM-DESIGN.md:699` (phase P6) names
that exact file, and it depends on P0–P5 — `routeCandidates`, `validateUpstreams`, `wan-failover`,
`nat.egressAware`, `show wan` — none of which exists outside that design document (`grep` finds
those words only in `docs/UPSTREAM-DESIGN.md`). Numbering here starts at `lab6` and leaves `lab5`
to that plan. Also left out: a lab per vendor, export/download of a lab from the UI (export already
exists, `web/app.js:2953`), and any change to `examples/build-examples.js`'s output format.
